# CoachLab

A beginner-friendly React and Express project for coaching lesson plans.
Phase 4 adds create/read lesson API routes backed by SQLite. The React lesson form is not implemented yet.

## Setup (Windows PowerShell)

Use Node.js 24.19.0 (the verified version) and npm.
From the CoachLab folder, run `npm ci` after cloning.
Then run `npm run db:migrate` to create your local database and apply the versioned schema.
If npm reports UNABLE_TO_VERIFY_LEAF_SIGNATURE, run `$env:NODE_USE_SYSTEM_CA = '1'` in that terminal and retry. This uses Windows trusted certificates without disabling TLS checks.

Open two terminals in the CoachLab folder:

```powershell
# Terminal 1: backend
npm run dev:server
```

```powershell
# Terminal 2: frontend
npm run dev:client
```

Open http://127.0.0.1:5173. The screen should show "Backend connected."
Stop each server with Ctrl+C. Both servers bind only to this computer.
Ports 3001 and 5173 must be available.

Run `npm run build` to check that the frontend compiles for production.

## Database setup and verification

The default SQLite location is `<Windows user home>/AppData/Local/CoachLab/coachlab.sqlite`, outside OneDrive.
`npm run db:migrate` creates the parent folder and database if needed. It applies `server/migrations/001_create_lessons.sql` and records version 1 in `schema_migrations`. Rerunning this command preserves existing lessons. Schema creation and its version record run together in a transaction: either both succeed or both are rolled back.
To override it, copy `.env.example` to `.env` in the project root and set DATABASE_PATH to an absolute file path outside OneDrive. Restart the backend after editing it.
Relative paths and paths with a OneDrive folder are rejected.
The `.env` file, database files, dependencies, and build output are ignored by Git.
The database path is backend-only; never use a VITE_ variable for private configuration.

Run `npm test` to verify configuration, schema constraints, migration reruns, transaction rollback, and persistence across separate Node processes. Tests use their own temporary database outside OneDrive and remove only their generated test directory; they do not change your normal CoachLab database.

The lessons table has the ten required columns. Title and discipline are required, skill level defaults to Beginner, duration is an optional positive integer, and goal/drills/coaching notes default to empty text. IDs are generated by SQLite and timestamps use UTC. Database constraints and API input validation both protect stored data.

The OneDrive path check recognizes normal OneDrive folder names; do not override the path with a custom synced folder or link into OneDrive. Native SQLite installation may need compiler tools if a prebuilt package is unavailable on another machine.

## How this setup works

- `client/src/App.jsx` is the React screen. State stores the connection message; an effect checks the backend when the screen loads.
- Vite serves the frontend and forwards `/api` requests to Express on port 3001.
- `server/index.js` opens one shared SQLite connection, runs the existing migrations, and starts the Express app defined in `server/app.js`. Startup stops with a safe terminal error if database initialization fails. Normal shutdown closes the connection.
- `server/config.js` chooses the database path; `server/database.js` opens it. `server/migrate.js` remains the standalone migration command. Startup also applies missing migrations without deleting records, so a fresh database can start predictably.
- `server/validate-lesson.js` checks incoming fields before a prepared SQL query inserts them. GET reads actual rows from that same database. React never accesses SQLite directly.
- A single root package.json keeps installation simple. package-lock.json records exact dependency versions.

## Lesson API (local backend)

Base URL: `http://127.0.0.1:3001`. GET `/api/health` remains available.

- `GET /api/lessons`: HTTP 200 with an array, empty when no lessons exist. Newest creation timestamp first, then highest ID to break timestamp ties.
- `POST /api/lessons`: send a JSON object with `Content-Type: application/json`. HTTP 201 returns the complete saved lesson including generated `id` and `created_at`.
- No PUT, PATCH, or DELETE route is implemented.

Validation rules:

| Field | Accepted values |
| --- | --- |
| title | Required nonblank string, at most 200 characters |
| discipline | Boxing, Wrestling, Muay Thai, Brazilian Jiu-Jitsu, MMA, Personal Training |
| skill_level | Beginner, Intermediate, Advanced; omitted defaults to Beginner |
| duration_minutes | Integer 1–1440, or null; omitted defaults to null |
| goal | Optional string, at most 2000 characters; omitted defaults to empty text |
| drills, coaching_notes | Optional strings, at most 10000 characters each; omitted defaults to empty text |

Text is trimmed; limits apply before trimming and are measured in JavaScript UTF-16 code units (some emoji count as two). Null is accepted only for duration. Unknown fields, including client-supplied IDs/dates, are rejected. Requests have a separate 32 KB JSON byte limit; multibyte text can reach this before the field limits.

Invalid fields or malformed JSON return HTTP 400 with an `error` message. Oversized request bodies return 413, unsupported encodings return 415, unknown routes return 404, and unexpected database errors return a generic 500. Internal SQL errors and stack traces are not sent to clients.

Example PowerShell requests using fake lesson data (the POST saves a real row if you run it):

```powershell
$lesson = @{
  title = "Demo jab practice"
  discipline = "Boxing"
  skill_level = "Beginner"
  duration_minutes = 30
  goal = "Practice accuracy"
  drills = "Three rounds of controlled jab practice"
  coaching_notes = "Demo notes"
} | ConvertTo-Json
Invoke-RestMethod -Uri "http://127.0.0.1:3001/api/lessons" -Method Post -ContentType "application/json" -Body $lesson
Invoke-RestMethod -Uri "http://127.0.0.1:3001/api/lessons" -Method Get
```

Run `npm test` for both database and real-HTTP API tests. They create isolated temporary SQLite databases, verify stored rows and reopened connections, and clean up afterward. They do not add lessons to your normal development database.
