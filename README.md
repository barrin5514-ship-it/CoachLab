# CoachLab

A beginner-friendly React and Express project for coaching lesson plans.
Phase 5 adds a React dashboard and lesson form connected to the Express API and persistent SQLite database.

## Setup (Windows PowerShell)

Use Node.js 24.19.0 (the verified version) and npm.
From the CoachLab folder, run `npm ci` after cloning.
Then run `npm run db:migrate` to create your local database and apply the versioned schema.
If npm reports UNABLE_TO_VERIFY_LEAF_SIGNATURE, run `$env:NODE_USE_SYSTEM_CA = '1'` in that terminal and retry. This uses Windows trusted certificates without disabling TLS checks.

Open two terminals in the CoachLab folder:

```powershell
# Terminal 1: backend
npm run dev:server
```

```powershell
# Terminal 2: frontend
npm run dev:client
```

Open http://127.0.0.1:5173. The dashboard loads your saved lessons, or explains how to create the first one.
Stop each server with Ctrl+C. Both servers bind only to this computer.
Ports 3001 and 5173 must be available. If 5173 is occupied, use `npm run dev:client -- --port 5174` and open http://127.0.0.1:5174 instead.

Run `npm run build` to check that the frontend compiles for production.

## Database setup and verification

The default SQLite location is `<Windows user home>/AppData/Local/CoachLab/coachlab.sqlite`, outside OneDrive.
`npm run db:migrate` creates the parent folder and database if needed. It applies `server/migrations/001_create_lessons.sql` and records version 1 in `schema_migrations`. Rerunning this command preserves existing lessons. Schema creation and its version record run together in a transaction: either both succeed or both are rolled back.
To override it, copy `.env.example` to `.env` in the project root and set DATABASE_PATH to an absolute file path outside OneDrive. Restart the backend after editing it.
Relative paths and paths with a OneDrive folder are rejected.
The `.env` file, database files, dependencies, and build output are ignored by Git.
The database path is backend-only; never use a VITE_ variable for private configuration.

Run `npm test` to verify configuration, schema constraints, migration reruns, transaction rollback, and persistence across separate Node processes. Tests use their own temporary database outside OneDrive and remove only their generated test directory; they do not change your normal CoachLab database.

The lessons table has nine columns: id, title, discipline, skill_level, duration_minutes, goal, drills, coaching_notes, and created_at. Title and discipline are required, skill level defaults to Beginner, duration is an optional positive integer, and goal/drills/coaching notes default to empty text. IDs are generated by SQLite and timestamps use UTC. Database constraints and API input validation both protect stored data.

The OneDrive path check recognizes normal OneDrive folder names; do not override the path with a custom synced folder or link into OneDrive. Native SQLite installation may need compiler tools if a prebuilt package is unavailable on another machine.

## How this setup works

- `client/src/App.jsx` loads lessons in an effect and stores the list and feedback in state. `LessonForm.jsx` manages controlled inputs and saves through POST. `LessonCard.jsx` receives a saved row through props and displays its details.
- Vite serves the frontend and forwards `/api` requests to Express on port 3001.
- `server/index.js` opens one shared SQLite connection, runs the existing migrations, and starts the Express app defined in `server/app.js`. Startup stops with a safe terminal error if database initialization fails. Normal shutdown closes the connection.
- `server/config.js` chooses the database path; `server/database.js` opens it. `server/migrate.js` remains the standalone migration command. Startup also applies missing migrations without deleting records, so a fresh database can start predictably.
- `server/validate-lesson.js` checks incoming fields before a prepared SQL query inserts them. GET reads actual rows from that same database. React never accesses SQLite directly.
- A single root package.json keeps installation simple. package-lock.json records exact dependency versions.

## Lesson API (local backend)

Base URL: `http://127.0.0.1:3001`. GET `/api/health` remains available.

- `GET /api/lessons`: HTTP 200 with an array, empty when no lessons exist. Newest creation timestamp first, then highest ID to break timestamp ties.
- `POST /api/lessons`: send a JSON object with `Content-Type: application/json`. HTTP 201 returns the complete saved lesson including generated `id` and `created_at`.
- No PUT, PATCH, or DELETE route is implemented.

Validation rules:

| Field | Accepted values |
| --- | --- |
| title | Required nonblank string, at most 200 characters |
| discipline | Boxing, Wrestling, Muay Thai, Brazilian Jiu-Jitsu, MMA, Personal Training |
| skill_level | Beginner, Intermediate, Advanced; omitted defaults to Beginner |
| duration_minutes | Integer 1–1440, or null; omitted defaults to null |
| goal | Optional string, at most 2000 characters; omitted defaults to empty text |
| drills, coaching_notes | Optional strings, at most 10000 characters each; omitted defaults to empty text |

Text is trimmed; limits apply before trimming and are measured in JavaScript UTF-16 code units (some emoji count as two). Null is accepted only for duration. Unknown fields, including client-supplied IDs/dates, are rejected. Requests have a separate 32 KB JSON byte limit; multibyte text can reach this before the field limits.

Invalid fields or malformed JSON return HTTP 400 with an `error` message. Oversized request bodies return 413, unsupported encodings return 415, unknown routes return 404, and unexpected database errors return a generic 500. Internal SQL errors and stack traces are not sent to clients.

Example PowerShell requests using fake lesson data (the POST saves a real row if you run it):

```powershell
$lesson = @{
  title = "Demo jab practice"
  discipline = "Boxing"
  skill_level = "Beginner"
  duration_minutes = 30
  goal = "Practice accuracy"
  drills = "Three rounds of controlled jab practice"
  coaching_notes = "Demo notes"
} | ConvertTo-Json
Invoke-RestMethod -Uri "http://127.0.0.1:3001/api/lessons" -Method Post -ContentType "application/json" -Body $lesson
Invoke-RestMethod -Uri "http://127.0.0.1:3001/api/lessons" -Method Get
```

Run `npm test` for both database and real-HTTP API tests. They create isolated temporary SQLite databases, verify stored rows and reopened connections, and clean up afterward. They do not add lessons to your normal development database.

## Classroom demo

1. Start both servers with the commands above. The backend applies any missing migrations automatically.
2. Click **New Lesson**, enter a title and choose one of the six disciplines. Beginner is the default skill level. Duration and all three detail fields are optional.
3. Try an empty title or duration 0: the form rejects invalid input. Enter a valid integer duration from 1 to 1440, or leave it blank.
4. Click **Save lesson**. While saving, controls are disabled; only a confirmed server response produces a success notice and card.
5. Refresh the page, then stop and restart both servers and refresh again. The saved lesson remains because SQLite stores it outside the project. Use the same DATABASE_PATH when restarting.
6. To demonstrate an outage, stop the backend and try saving a new draft. The error retains the input. Restart the backend to recover. If the connection was interrupted during a save, check the saved list before retrying because a request can reach the server even when its response is lost.

Demo submissions create real records in the selected database. For disposable demos, set DATABASE_PATH in the backend terminal to a new absolute path outside OneDrive, such as `$env:DATABASE_PATH = Join-Path $env:TEMP "coachlab-class-demo.sqlite"`, before starting it. Do not delete your regular database. No Update/Delete or authentication is included in this phase.

## Phase 8A: single-lesson AI drafts

Click **AI lesson draft** and enter discipline, skill level, 15–180 whole minutes, 1–100 students, a training objective, techniques and equipment. All six existing disciplines are supported. Use generic class details only; no names, health information or other personal athlete information. Google's free tier may use requests/responses to improve products. The privacy checkbox is an affirmation, not an automatic personal-information filter.

The server requests five timed sections: warm-up, technique teaching, progressive drills, partner exercises and cooldown. It requires objectives, technique content, mistakes, corrections, skill modifications and safety text. The model is instructed to provide step-by-step coaching; structural checks cannot certify its technical accuracy. A qualified coach must review every draft. All section minutes must sum exactly to the requested duration; only partner work may use zero with a solo alternative.

Edit any draft text or section time, then check the approval box and click **Approve and save lesson**. Any edit clears previous approval. Generation itself writes nothing to SQLite. Approved drafts become new lessons through the existing POST /api/lessons route, with structured content formatted into goal, drills and coaching_notes. They display through the existing lesson cards. Existing lessons are never overwritten. No migration or new dependency was required.

Drafts survive failed saves while this page stays open. They are not autosaved and will be lost on refresh, closing the tab or explicit discard. If a save response is interrupted, check the saved list in another tab before retrying: the server may have saved it even if the reply was lost. Approval is a local UI workflow, not authentication or a server-side identity audit. Saved lessons have no Update/Delete UI.

### Safe Gemini setup

1. In Google AI Studio, use an eligible project with **billing disabled**. No paid plan is required by CoachLab. Verify availability and your actual project limits there.
2. Copy the blank .env.example to a new .env file only if .env does not already exist. Do not put the key in .env.example, which is tracked by Git. On Windows ensure the private file is named .env, not .env.txt.
3. Set GEMINI_API_KEY only in ignored .env. Optional server settings are AI_PROVIDER=gemini and AI_MODEL=gemini-3.5-flash-lite. Never use a VITE_ key variable. Restart Express after configuration changes. Keep DATABASE_PATH outside OneDrive. On this machine, set `$env:NODE_USE_SYSTEM_CA = '1'` in the backend terminal before starting Express so Node uses Windows trusted certificates; this does not disable TLS verification.
4. Start the app with the existing commands: npm run dev:server and npm run dev:client. If AI is unconfigured or unavailable, manual New Lesson still works.

Provider research on 2026-10-15: Google's [model catalog](https://ai.google.dev/gemini-api/docs/models) lists gemini-3.5-flash-lite as stable. Its [pricing page](https://ai.google.dev/gemini-api/docs/pricing) lists free input/output and paid rates of $0.30/$2.50 per million input/output tokens; rates can change. A real generic sixty-minute BJJ request succeeded with this model and passed structural/duration validation. gemini-3.8-flash was also documented and returned by this key's model-list API, but its generation endpoint returned 503 UNAVAILABLE, so it was not selected as the default. Paid billing was not enabled. [Rate-limit documentation](https://ai.google.dev/gemini-api/docs/rate-limits) directs users to AI Studio for account-specific RPM/TPM/RPD limits; no numeric Google quota is assumed here. [Data terms](https://ai.google.dev/gemini-api/terms) describe free-tier data use.

The server uses Google's [generateContent REST endpoint](https://ai.google.dev/api/generate-content), structured JSON, a 45-second timeout, 8192 maximum output tokens and a 64KiB downloaded-response limit. Express already limits JSON bodies to 32KiB; drafts are also checked against saved-field lengths and a 32000-byte save budget. The app permits one generation at a time, three accepted attempts per rolling minute and twenty per rolling 24 hours, including failed attempts. These in-memory limits reset when Express restarts and are not a billing cap or Google's quota. There are no automatic retries.

The current adapter supports Gemini only; provider/model configuration and the separate adapter boundary allow later providers without changing the UI contract. An unknown provider fails safely. AI errors contain safe messages rather than provider bodies or keys. The local server stays loopback-only; deployment/security for public hosting is outside this phase.
